# Taste — General Preferences
- Prefers the agent to fully inspect the project and report findings before making any changes; explicitly says not to write or edit code until the inspection is complete ("report only, do not fix or change anything yet", "investigate only, don't fix yet ... no code changes"). Confidence: 0.8
- Wants definitive, evidence-backed verdicts on whether claimed components are actually wired into the running app (dependencies, config modules, env vars, containers) versus merely present as dead code, rather than assuming presence means usage. Confidence: 0.55
- Wants documented results written to a report file at the specific path/name the user specifies (e.g. `docs/COMMANDCODE_INSPECTION.md`, or a root-level file named exactly as given), and also echoed/printed in chat; written reports should follow a fixed, itemized section ordering and end with an explicit stop line. Confidence: 0.65
- Expects changes scoped strictly to the single task requested; explicitly forbids touching anything else and wants to review the result before the agent proceeds to further work ("fix only X, do not touch anything else yet", "do not proceed to anything else ... until I review this"). Confidence: 0.75
- Supplies exact git commit messages and expects them used verbatim, staging only the specific files named (no unrelated changes swept in). Confidence: 0.6
- Expects git operations to be verified afterwards (e.g. running `git log --oneline` to confirm the commit landed and shows the right files). Confidence: 0.6
- Favors conventional-commit style messages with a type prefix (`fix:`, `feat:`, `docs:`, `test:`). Confidence: 0.5
- Wants existing reports, docs, and prior claims cross-checked and verified independently, not repeated at face value. Confidence: 0.6
- Prefers granular, itemized metrics (e.g. exact counts per phase/section) over aggregate totals. Confidence: 0.55
- When running tests or commands that could trigger real external side effects, wants real credentials/API keys disabled by commenting them out (not deleting) so they can be easily uncommented and restored later. Confidence: 0.7
- Treats a designated spec/requirements doc as the source of truth for behaviour; when code, roadmap, and spec disagree, wants the conflict surfaced explicitly (logged as a "Needs decision" row in a ledger file and mentioned in the report) rather than silently resolved. Confidence: 0.7
- Wants the agent to STOP and ask when a requirement is ambiguous or the task prompt conflicts with the repo, rather than guessing or picking silently. Confidence: 0.65
- Favors an architecture where UI/screens never call HTTP clients or fixtures directly, but go through a hooks/data-service layer ("data ports"); domain types come from a single documented source of truth and no new fields are invented. Confidence: 0.65
- Requires mock/fixture data to be realistic and production-like (real names, place names, currency amounts, ID/tracking-number formats) — no lorem ipsum and no placeholder names like "John Doe" or "Test". Confidence: 0.7
- Forbids artificial latency in UI code: no `setTimeout`/`new Promise` delays in screens or hooks; any simulated delay must come from one configurable mock transport. No fake servers or MSW. Confidence: 0.7
- Insists on strict design-system discipline: only shared tokens/components, no hex literals, no magic spacing, no one-off styles, and every screen must render correctly in both light and dark themes. Confidence: 0.7
- Wants UI reuse enforced — no duplicated UI (extract shared components), no dead navigation — and every screen to implement loading, empty, error, and (where relevant) offline states. Confidence: 0.65
- Restricts dependencies to an explicit pre-approved list, prefers `npx expo install` for Expo packages, and expects the agent to list any additional needed dependency and wait for approval rather than installing it. Confidence: 0.7
- Requires real command output pasted as evidence for every validation step, and explicitly wants failed or unrunnable checks reported honestly alongside a list of "unknowns I could not determine" rather than a bare success claim. Confidence: 0.7
- Does not want the agent to commit, push, branch, stash, or reset on its own; wants a proposed conventional-commit message and exact file list presented for approval, committing only after that approval. Confidence: 0.65
