## Scope Verification (per DEVELOPMENT_ROADMAP.md Phase 6)

### Backend Payments Module
- [x] FR-C06: Paystack and Flutterwave integration
- [x] Pay-before-assignment enforcement: Delivery status must be REQUESTED to initiate payment
- [x] REQUESTED → SEARCHING transition only on confirmed payment (via webhook or manual verification)
- [x] Webhook/callback handling with signature validation for both Paystack and Flutterwave
- [x] Idempotency on duplicate webhook delivery (checks payment status before processing)

### Payment Entity
- [x] Payment entity with all required fields: reference, provider, status, amount, currency, channel, customer info, gateway response
- [x] PaymentProvider enum: PAYSTACK, FLUTTERWAVE
- [x] PaymentStatus enum: PENDING, PROCESSING, SUCCESS, FAILED, CANCELLED, REFUNDED
- [x] PaymentChannel enum: CARD, BANK_TRANSFER, USSD, MOBILE_MONEY, QR_CODE
- [x] Webhook retry tracking and idempotency

### Payment Service
- [x] Initialize payment (Paystack/Flutterwave) with delivery validation
- [x] Verify payment status (manual and via webhook)
- [x] Handle Paystack webhook (charge.success, charge.failed) with HMAC-SHA512 signature verification
- [x] Handle Flutterwave webhook (charge.completed, charge.failed) with HMAC-SHA256 signature verification
- [x] Process successful payment: updates payment status, sets delivery to SEARCHING
- [x] Process failed payment: updates payment status, records failure reason
- [x] Idempotency: checks existing payment status before processing

### API Endpoints
- [x] POST /payments/initialize (customer) - Initialize payment for delivery
- [x] GET /payments/:reference (customer/rider/admin) - Get payment by reference
- [x] GET /payments/delivery/:deliveryId (customer/rider/admin) - Get payment for delivery
- [x] POST /payments/verify/:reference (customer) - Manually verify payment
- [x] POST /payments/webhook/paystack - Paystack webhook endpoint
- [x] POST /payments/webhook/flutterwave - Flutterwave webhook endpoint
